# UI 视觉与主题规范

日期：2026-06-03

## 设计方向

本项目采用现代、简洁、开发者工具感的视觉方向。整体气质参考 GitHub 官网和 GitHub Discussions 一类开发者产品的清晰度、克制灰阶、内容优先和工程感，但不复刻 GitHub 的品牌、图标、Logo 或具体页面。

关键词：

- 现代简洁
- 内容优先
- 低信息密度
- 中性灰阶
- 浅色/深色模式一致
- 面向技术讨论和社区分享

## 视觉原则

- 页面先服务阅读、搜索、发帖、评论和审核，不做营销型 hero。
- 信息密度保持中低水平：列表不要铺满屏幕，模块之间保留明显留白。
- 颜色以中性灰阶为主，蓝色作为主要操作色，绿色、橙色、红色只用于状态反馈。
- 前台偏内容阅读和社区互动，后台偏任务处理和治理效率，但两者共享同一套主题变量。
- 卡片只用于独立内容块、列表项、表单区域和后台统计块，不做卡片套卡片。
- 圆角控制在 `6px` 到 `8px`，保持工具型产品的克制感。
- 图标使用简洁线性风格，优先用于按钮、导航、状态和操作入口。

## 信息密度

前台默认采用低信息密度布局：

- 首页首屏只展示核心入口、少量最新主题、少量热门标签和主要分区。
- 主题列表默认展示 `4` 到 `8` 条关键内容，更多内容通过分页、加载更多或筛选进入。
- 主题详情页优先保证正文、代码块和评论可读性，不在侧边栏堆过多统计信息。
- 个人主页展示用户资料、发布历史和收藏等关键模块，避免一次性展示所有用户行为。

后台采用中低信息密度布局：

- 仪表盘只展示关键待办、待处理举报、近期审核和少量指标。
- 审核表格默认控制列数，优先展示内容摘要、举报原因、状态、时间和操作。
- 复杂筛选进入折叠筛选区或独立筛选栏，不挤占主表格。
- 状态色只用于待处理、已通过、已隐藏、已封禁等明确状态。

## 主题模式

第一版必须支持浅色模式和深色模式切换：

- 支持 `light`、`dark`、`system` 三种主题偏好。
- 默认跟随系统主题。
- 用户切换后在本地持久化。
- 前台和后台共享主题实现和主题变量。
- 服务端渲染页面避免明显闪烁，初始主题应尽量在页面加载前确定。

推荐实现：

- 使用 CSS variables 定义 design tokens。
- 在根节点上使用 `data-theme="light"` 或 `data-theme="dark"`。
- Next.js 应用可使用 `next-themes` 或等价的轻量封装。
- 主题切换按钮放在顶部导航右侧，使用图标按钮并提供可访问标签。

## 页面布局

前台页面：

- 顶部导航：站点名、搜索、主要导航、通知、主题切换、用户入口。
- 首页：左侧少量分区入口，中间主题列表，右侧热门标签或社区动态。
- 分区页：分区说明、筛选排序、主题列表。
- 主题详情页：正文主列优先，右侧只放作者、标签、相关主题等轻量信息。
- 发布页：标题、分区、标签、Markdown 编辑器和预览区，操作区保持固定且清晰。

后台页面：

- 左侧导航：仪表盘、内容审核、举报处理、用户管理、分区管理、标签管理、审计日志。
- 顶部区域：搜索、当前管理员、主题切换。
- 主区域：单一主要任务优先，不在同一屏塞满多个复杂表格。
- 操作按钮：审核、隐藏、恢复、封禁等危险操作必须有明确状态反馈和确认步骤。

## 组件规则

- 按钮分为 `primary`、`secondary`、`ghost`、`danger`。
- 表单控件使用清晰边框、聚焦态和错误提示，不依赖颜色作为唯一反馈。
- 标签使用轻量 pill 样式，颜色克制，不为每个标签随机配色。
- 代码块使用等宽字体、清晰背景和可复制按钮。
- 列表项保持稳定高度，hover 只改变背景或边框，不造成布局跳动。
- 主题切换使用图标按钮，浅色显示月亮或系统图标，深色显示太阳或系统图标。

## 可访问性

- 文本和背景对比度必须满足常规阅读需求。
- 所有图标按钮必须有 `aria-label`。
- 表单错误需要文字说明。
- 键盘可以访问导航、搜索、发布、评论和后台主要操作。
- 深色模式不能只反转颜色，要保证边框、代码块和状态色仍然清晰。

## 不做

- 不做大面积渐变背景。
- 不使用装饰性光斑、圆球、bokeh 或纯氛围背景。
- 不做营销型首页 hero。
- 不使用 GitHub Logo、Octocat 或现成品牌资产。
- 不把后台做成高密度数据大屏。
- 不让页面被彩色标签和状态色主导。
